Playlists met een gezicht

De web UI heeft de Spotify-tokens al. De Android app en Android Auto tonen dezelfde playlists als tekstregels met een generiek icoon. Dit voorstel geeft elke playlist een cover die de app zelf maakt — uit het genre, het festival of de DJ — zodat één beeldsysteem web, telefoon en auto bedient.

De kleur is afgeleid, niet gekozen

// Vaste tabel voor de genres die de collectie dragen, hash voor de rest.
object GenrePalette {
    private val known = mapOf(
        "hardstyle" to 0xFFFF4D00,
        "hardcore"  to 0xFFE5002B,
        "techno"    to 0xFF00E0C7,
        "trance"    to 0xFF7B2DFF,
        "house"     to 0xFFFFB400,
    )

    fun tintFor(name: String): Int {
        val key = name.lowercase().trim()
        known[key]?.let { return it.toInt() }
        // Zelfde naam, zelfde kleur -- op telefoon en in de auto.
        val hue = (key.hashCode().absoluteValue % 360).toFloat()
        return Color.HSVToColor(floatArrayOf(hue, 0.82f, 0.95f))
    }
}

Dezelfde tabel hoort in de web UI te staan, anders is Hardstyle daar oranje en hier magenta. Zet hem in de server-response naast de genre-naam, dan hoeft geen van beide clients hem te kennen.

In de auto

Android Auto rendert wat de app aanlevert. Nu levert MuMa geen content-style hint en geen artwork voor browsable items, dus het hoofd wordt een tekstlijst met standaardicoontjes. Met een grid-hint en een artwork-URI wordt het ditzelfde beeld — zonder dat er een schermontwerp voor de auto bestaat.

De twee regels code die dit aanzetten

// MediaItemConverter.kt -- deze constanten staan er nog niet in.
private const val CONTENT_STYLE_BROWSABLE =
    "android.media.browse.CONTENT_STYLE_BROWSABLE_HINT"
private const val CONTENT_STYLE_PLAYABLE =
    "android.media.browse.CONTENT_STYLE_PLAYABLE_HINT"
private const val GRID_ITEM = 2
private const val LIST_ITEM = 1

extras.putInt(CONTENT_STYLE_BROWSABLE, GRID_ITEM)  // genres, festivals, DJ's
extras.putInt(CONTENT_STYLE_PLAYABLE,  LIST_ITEM)  // tracks en sets
// De cover komt van dezelfde content provider als album art,
// zodat Auto hem zonder netwerkrechten mag laden.
val art = AlbumArtContentProvider.mapPlaylistArtUri(
    kind = PlaylistArtKind.GENRE,
    key  = genre.name,
)

buildMediaItem(
    title       = genre.name,
    mediaId     = "genre|" + genre.name,
    isBrowsable = true,
    isPlayable  = false,
    imageUri    = art,
)

Zonder CONTENT_STYLE_BROWSABLE_HINT negeert Auto de artwork-URI voor browsable items grotendeels: het valt terug op een lijst met een klein icoon. De cover renderen zonder de hint te zetten levert dus geen zichtbaar verschil op.
